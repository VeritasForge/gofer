# gofer holiday 설계 — 쉬는 날에는 그래프를 갱신하지 않는다

작성일: 2026-09-12
상태: 설계 승인됨, 구현 플랜 작성 전

## 1. 무엇을, 왜

`ua-refresh`는 매일 아침 지식 그래프를 갱신하고 Slack DM을 두 통(시작 1건, 결과 1건) 보낸다. 주말과 공휴일에도 똑같이 보내므로, **쉬는 날에도 알림이 온다.** 이 알림을 없애는 것이 이 작업의 목적이다.

쉬는 날 판정에 필요한 한국 공휴일 목록은 `ua-refresh` 전용으로 두지 않고, 앞으로 다른 도구도 쓸 수 있도록 **`holiday`라는 독립 도구이자 공용 패키지**로 만든다.

두 가지를 나눠 보면 이렇다.

```
gofer holiday      새 도구. 공휴일 목록을 내려받아 저장하고, 날짜 하나가 쉬는 날인지 판정한다
                   └─ 다른 도구가 코드로 부르는 공용 패키지이기도 하다

gofer ua-refresh   기존 도구. 아침에 holiday 에게 "오늘 쉬는 날인가"를 묻고,
                   쉬는 날이면 아무것도 하지 않고 끝낸다
```

### 목표

- `gofer holiday sync` 한 번으로 공휴일 목록을 내려받아 로컬에 저장한다. 매일 아침 돌아가는 경로는 이 저장된 파일만 읽고 네트워크를 쓰지 않는다.
- 토요일·일요일·공휴일·대체공휴일에는 `ua-refresh`가 실행되지 않고, Slack 알림도 가지 않는다.
- **저장된 목록이 오늘을 덮지 못할 때만 그 자리에서 한 번 스스로 내려받아 회복한다.** 사람이 `sync`를 잊어도 조용히 망가지지 않는다.
- 목록이 없거나 낡았고 자동 회복까지 실패했을 때도 최소한 주말은 걸러 내고, **그 사실을 Slack 알림에 실어 사람에게 알린다.**
- 날짜를 고정해 시험할 수 있다. 네트워크에 나가는 시험은 만들지 않는다.

### 목표가 아닌 것

- 다음 영업일 계산, 기간 내 영업일 세기, 달력을 여러 벌 동시에 두기. 지금 쓰는 곳이 없다. 필요해지면 짧은 함수로 붙는다.
- 임시공휴일 자동 추적. 정부가 갑자기 지정하는 날은 저장된 목록의 수록 기간 안이라 프로그램이 낡았다고 판단할 근거가 없다. `sync`를 다시 돌리거나 설정의 `extra`에 한 줄 적어서 넣는다.
- 주기적인 자동 갱신. 목록이 오늘을 덮지 못할 때만 한 번 시도하고, 그 밖에는 사람이 `sync`를 직접 돌린다. 갱신 전용 예약 작업을 따로 만들지 않는다.

### 기존 설계와 달라지는 점

`ua-refresh` 설계 문서는 "주말 제외"를 **목표가 아닌 것**으로 적어 두었다. 이 문서가 그 결정을 뒤집는다. 당시 판단의 근거는 "변경이 없으면 어차피 비용이 0"이었는데, 알림은 비용과 무관하게 매일 오므로 그 근거로는 알림 소음이 해결되지 않는다.

## 2. 전제 조건

### 공휴일 목록을 어디서 받는가 (직접 확인함)

인증 없이 받을 수 있는 구글 공개 달력(대한민국의 휴일)을 쓴다. 2026-09-12에 실제로 내려받아 확인한 내용은 다음과 같다.

| 확인 항목 | 결과 |
|---|---|
| 응답 | HTTP 200, 약 98 KiB |
| 수록 범위 | 2021년부터 2031년까지, 공휴일 205건 |
| 공휴일과 기념일 구분 | `DESCRIPTION` 값이 `공휴일`(205건)과 `기념일`(75건)로 나뉜다. 식목일·어버이날·스승의날은 기념일로 분류되어 걸러진다 |
| 대체공휴일 | `쉬는 날 삼일절`처럼 별도 항목으로 들어 있다 |
| 음력 공휴일 | 설날·추석·부처님오신날이 연도별로 정확한 날짜로 들어 있다. 음력 변환 코드가 필요 없다 |
| 연휴 표현 | 연휴의 각 날이 하루짜리 항목으로 따로 들어 있다 |
| 임시공휴일 | 2025-01-27(설 연휴 임시공휴일), 2024-10-01(국군의날 임시공휴일)이 실제로 들어 있다 |

### 이 목록이 완벽하지 않다는 것도 확인함

같은 검증에서 **가장자리가 어긋나는 대목**을 두 가지 찾았다. 그래서 사람이 손으로 보정할 수 있는 길을 설계에 넣는다.

| 어긋남 | 내용 |
|---|---|
| 누락 | 2024년 추석 연휴 사흘 중 9월 16일이 빠져 있고 17·18일만 들어 있다 |
| 연도별 불일치 | 노동절(5월 1일)이 2025년 목록에는 없는데 2026·2027년 목록에는 공휴일로 들어 있다. 제헌절(7월 17일)도 2025년까지 없다가 2026년부터 들어 있다 |

제헌절이 공휴일로 다시 지정되었는지는 **확인하지 못했다.** 노동절은 관공서 공휴일이 아니지만 많은 회사가 쉬므로, 어느 쪽이 옳은지는 쓰는 사람마다 다르다. 둘 다 목록이 주는 대로 쉬는 날로 두고, 설정 파일 주석으로 "필요하면 제외 목록에 넣으라"고 안내한다. 판정이 틀렸을 때의 손해는 **알림 두 건이 더 오거나, 그날 그래프 갱신이 하루 밀리는 정도**다.

### launchd로는 공휴일을 걸러 낼 수 없다 (`man launchd.plist` 확인함)

`StartCalendarInterval`에는 `Minute`·`Hour`·`Day`·`Weekday`·`Month` 키가 있어 **요일 조건까지는 지정할 수 있지만 공휴일 조건은 지정할 수 없다.** 따라서 공휴일 판정은 어차피 프로그램 안에서 해야 한다. 그렇다면 주말도 같은 자리에서 함께 판정해 **판정 지점을 한 곳으로 모은다.** plist는 지금처럼 매일 같은 시각으로 두고 건드리지 않는다. 이 선택 덕분에 이미 `install`을 마친 사용자가 plist를 다시 설치할 필요도 없다.

## 3. 사용법

```
gofer holiday sync                  공휴일 목록을 내려받아 저장한다 (사람이 가끔 실행)
gofer holiday list [연도]           저장된 목록을 본다 (연도 생략 시 올해)
gofer holiday check [YYYY-MM-DD]    그날이 쉬는 날인지 본다 (생략 시 오늘)

gofer ua-refresh run                쉬는 날이면 한 줄 출력하고 바로 끝낸다
gofer ua-refresh run --force        쉬는 날이라도 실행한다
```

### 설정 파일 `~/.config/gofer/holiday.toml`

이 파일은 **사람만 쓴다.** `sync`는 이 파일을 읽기만 하고 절대 쓰지 않으므로, 손으로 적어 둔 내용이 `sync`로 날아가지 않는다. 파일이 없어도 모든 명령이 동작한다. 이때 주소는 아래 기본값을 쓰고, 더하거나 뺄 날짜는 없는 것으로 본다.

```toml
# 내려받을 달력 주소. 비우거나 이 파일이 없으면 대한민국 공휴일 달력을 쓴다.
url = "https://calendar.google.com/calendar/ical/ko.south_korea%23holiday%40group.v.calendar.google.com/public/basic.ics"

# 달력에 없지만 쉬는 날로 칠 날짜. 임시공휴일이 갑자기 지정됐을 때 여기에 적는다.
extra = []

# 달력에 있지만 쉬는 날로 치지 않을 날짜.
# 이 달력은 노동절(5/1)과 제헌절(7/17)을 공휴일로 싣는데, 연도마다 기준이 다르고
# 관공서 기준과도 어긋난다. 그날 일한다면 여기에 적는다.
ignore = []
```

### 저장 파일 `~/Library/Application Support/gofer/holiday/calendar.json`

이 파일은 **`sync`만 쓴다.** 사람이 고칠 필요가 없고, 고쳐도 다음 `sync`에 덮인다.

```json
{
  "synced_at": "2026-09-12T14:03:11+09:00",
  "source": "https://calendar.google.com/calendar/ical/…",
  "covers": {"from": "2021-01-01", "to": "2031-12-31"},
  "holidays": [
    {"date": "2026-01-01", "name": "새해첫날"},
    {"date": "2026-03-02", "name": "쉬는 날 삼일절"}
  ]
}
```

`covers`는 이 목록이 어느 기간을 담고 있는지다. 판정할 날짜가 이 범위 밖이면 **공휴일 여부를 모른다**는 뜻이므로, 그 사실을 경고로 알린다.

### `~/.config/gofer/ua-refresh.toml`에 늘어나는 한 줄

```toml
[schedule]
at            = "07:30"
workdays_only = true      # 토·일·공휴일에는 실행하지 않는다
```

**기본값은 켜짐이다.** `config init`이 만드는 템플릿에도 `true`로 들어간다. 기존 설정 파일에 이 항목이 없으면 어떻게 볼지가 문제인데, 없을 때도 켜진 것으로 본다 — 이 도구를 쓰는 사람이 쉬는 날 알림을 원하지 않는다는 것이 이 작업의 출발점이기 때문이다. 끄려면 `false`를 명시한다.

여기에 구현상 함정이 하나 있다. Go에서 `bool` 항목은 값이 없으면 자동으로 `false`가 되므로, **그냥 읽으면 "항목 없음"과 "`false`라고 적음"이 구별되지 않아 기본값이 꺼짐으로 뒤집힌다.** 설정을 읽을 때 항목이 실제로 적혀 있었는지를 함께 확인해야 한다. 이 레포는 이미 같은 라이브러리의 해석 결과를 받아 알 수 없는 항목을 걸러 내고 있으므로, 같은 결과에서 "이 항목이 정의되었는가"를 함께 보면 된다.

### 파일 위치

| 무엇 | 경로 |
|---|---|
| `holiday` 설정 (사람이 씀) | `~/.config/gofer/holiday.toml` |
| 내려받은 목록 (`sync`가 씀) | `~/Library/Application Support/gofer/holiday/calendar.json` |

기존 규칙(설정은 `~/.config/gofer/<도구>.toml`, 프로그램이 만드는 상태는 `~/Library/Application Support/gofer/<도구>/`)을 그대로 따른다.

## 4. 동작

### 쉬는 날 판정

```
쉬는 날이다  ⟸  토요일이거나 일요일이다
             또는  (내려받은 목록에 있다  +  설정의 extra 에 있다)  −  설정의 ignore 에 있다
```

`ignore`가 가장 세다. 목록에 있고 `extra`에도 있어도 `ignore`에 있으면 일하는 날이다.

기준 시각은 **기계의 로컬 시각**이다. launchd 예약 자체가 로컬 시각을 따르므로 이쪽에 맞춘다. 한국 시간대를 쓰는 기계에서는 차이가 없고, 해외 체류 중이면 현지 날짜로 판정된다.

### 목록이 없거나 낡았을 때: 한 번 스스로 받아 보고, 그래도 안 되면 알린다

목록을 못 읽는 상황에서 **아무것도 실행하지 않는 쪽으로 기울면, 그래프가 조용히 며칠씩 늙어도 아무도 모른다.** 반대로 기울면 최악이 알림 두 건이므로, 판정할 수 없을 때는 실행하는 쪽으로 간다. 다만 주말 판정은 파일 없이도 되므로 그것만은 계속 적용한다.

여기에 더해, **목록이 오늘을 덮지 못하는 바로 그때만 한 번 내려받아 본다.**

```
ua-refresh run
   │
   ├─ 저장된 목록이 오늘을 덮는가?
   │      예 ──▶ 그대로 판정. 네트워크를 쓰지 않는다          ← 평소 (확인 결과 5년 이상)
   │      아니오
   │        │
   │        ├─ 그 자리에서 한 번 내려받기
   │        │     성공 ──▶ 새 목록으로 판정. 사람은 아무것도 하지 않아도 된다
   │        │     실패 ──▶ 주말만 판정 + 경고를 Slack 알림에 실어 보낸다
```

내려받기를 평소 경로에 두지 않는다는 원칙은 그대로다. 확인한 달력이 2031년까지 담고 있으므로 **앞으로 5년 넘게 이 자동 회복 경로는 한 번도 실행되지 않는다.** 그 뒤 어느 날 목록이 소진됐을 때만 한 번 동작한다.

| 상황 | 자동 회복 시도 | 주말 판정 | 공휴일 판정 | 경고 |
|---|---|---|---|---|
| 저장 파일 없음 (`sync` 미실행) | 한다 | 적용 | 회복하면 적용 | 회복 실패 시에만 |
| 저장 파일이 깨짐 | 한다 | 적용 | 회복하면 적용 | 회복 실패 시에만 |
| 오늘이 `covers` 범위 밖 | 한다 | 적용 | 회복하면 적용 | 회복 실패 시에만 |
| 정상 | 하지 않는다 | 적용 | 적용 | 없음 |

`--dry-run`은 자동 회복을 하지 않는다. 무엇을 할지 보여주기만 하는 명령이 저장 파일을 바꾸면 놀랍기 때문이다. 이때는 경고만 낸다.

### `ua-refresh run`의 흐름

```
gofer ua-refresh run
   │
   ├─ ① 설정 읽기 (기존)
   │
   ├─ ② workdays_only 가 켜져 있고 --force 가 없으면, 오늘이 쉬는 날인지 본다
   │      │
   │      쉬는 날 ──▶ 한 줄 출력하고 종료 (종료 코드 0)
   │                   · Slack 전송 없음               ← 이 작업의 목적
   │                   · 일별 로그 파일을 만들지 않음
   │                   · last-run.json 을 건드리지 않음
   │                   · 잠금 파일을 잡지 않음
   │
   └─ 일하는 날 ──▶ ③ 잠금 → ④ 로그 → ⑤ 시작 DM → ⑥ 레포별 처리 → ⑦ 결과 DM (기존 그대로)
```

`last-run.json`을 건드리지 않는 이유는, `status`가 보여주는 "마지막 실행"이 건너뜀으로 덮이면 **직전에 실제로 무엇이 갱신됐는지를 잃기 때문**이다. 일별 로그 파일을 만들지 않는 이유도 같다. 쉬는 날에 빈 로그 파일이 쌓일 이유가 없다. 건너뛰었다는 한 줄은 표준 출력으로 나가고, launchd가 그것을 `launchd.log`에 받아 적으므로 흔적은 남는다.

### 사람이 직접 실행할 때도 똑같이 건너뛴다

launchd가 부른 것인지 사람이 친 것인지를 출력이 터미널인지 보고 구분할 수도 있지만, 그렇게 하면 `gofer ua-refresh run | tee log.txt`처럼 출력을 파이프로 넘기는 순간 사람이 친 것인데도 건너뛰어 **동작을 예측하기 어려워진다.** 그래서 부른 사람이 누구든 판정은 같고, 예외는 눈에 보이는 `--force` 플래그로만 만든다.

`--dry-run`은 쉬는 날이어도 지금처럼 전부 보여준다. 무엇을 할지 확인하는 용도이므로 막을 이유가 없고, 맨 위에 오늘의 판정 한 줄만 덧붙인다.

## 5. 코드 구조

```
cmd/
├── root.go              root.AddCommand(holiday.Cmd()) 한 줄 추가
├── holiday/             새 도구. 플래그 파싱만
│   ├── holiday.go       부모 커맨드
│   ├── sync.go  list.go  check.go
└── uarefresh/
    └── run.go           --force 플래그 추가

internal/
├── holiday/             새 공용 패키지
│   ├── calendar.go      Calendar 타입과 판정
│   ├── store.go         calendar.json 읽기·쓰기, 설정 읽기

│   └── paths.go         파일 위치
```

`holiday`는 **명령을 가진 도구이면서 다른 도구가 코드로 부르는 공용 패키지**다. 기존에는 `slack`처럼 명령 없는 라이브러리와 `uarefresh`처럼 명령 있는 도구만 있었으므로, 이 성격이 처음이다. 규칙 자체는 그대로 지킨다 — `cmd/`는 얇게, 로직은 `internal/`에.

### 다른 도구에 내놓는 것

```go
// Open 은 설정과 저장된 목록을 함께 읽어 판정용 달력을 만든다. 네트워크를 쓰지 않는다.
// 저장 파일이 없거나 깨져 있어도 오류를 내지 않고, 주말만 아는 달력과 경고 문구를 돌려준다.
func Open(p Paths, now time.Time) (*Calendar, string, error)

// OpenOrRefresh 는 Open 과 같되, 저장된 목록이 now 를 덮지 못할 때만 그 자리에서
// 한 번 내려받아 본다. 목록이 유효한 동안에는 네트워크를 쓰지 않는다.
func OpenOrRefresh(ctx context.Context, p Paths, now time.Time) (*Calendar, string, error)

// IsWorkday 는 그날이 일하는 날인지 본다.
func (c *Calendar) IsWorkday(t time.Time) bool

// Holiday 는 그날이 쉬는 날이면 이유를 돌려준다 ("주말", "설날", "쉬는 날 삼일절").
func (c *Calendar) Holiday(t time.Time) (reason string, off bool)
```

`Open`이 오류 대신 경고 문구를 돌려주는 이유는, **부르는 쪽이 매번 "파일이 없으면 어떻게 하지"를 다시 정하지 않게 하기 위해서**다. 판정할 수 없을 때 실행하는 쪽으로 기운다는 정책이 이 패키지 안에 들어 있고, 부르는 쪽은 경고 문구를 로그에 옮기기만 하면 된다. 오류를 돌려주는 경우는 하나뿐이다 — **설정 파일 자체가 잘못 적혀 있을 때**다. 사람이 고쳐야 하는 문제이므로 조용히 넘기지 않는다. 내려받은 목록이 없거나 깨진 것은 오류가 아니라 경고다.

### 달력 파일 해석에서 주의할 점

내려받는 형식은 일정 교환용 텍스트 형식(iCalendar)이다. 표준 라이브러리만으로 해석하며 의존성은 늘리지 않는다. 실제 파일을 보고 확인한 주의점은 세 가지다.

- 줄바꿈이 `CRLF`다. 캐리지 리턴을 떼지 않고 값을 비교하면 `DESCRIPTION`이 `공휴일`인지 보는 판정이 통째로 실패한다. 검증 과정에서 실제로 겪었다.
- 긴 줄은 여러 줄로 접혀 들어온다. 다음 줄이 공백이나 탭으로 시작하면 앞줄에 이어 붙인 뒤에 해석해야 한다.
- 끝 날짜(`DTEND`)는 그날을 포함하지 않는다. 1월 1일 하루짜리 항목은 시작 1월 1일, 끝 1월 2일로 들어온다.

### 의존성

늘지 않는다. 내려받기는 표준 라이브러리 `net/http`, 저장 파일은 `encoding/json`, 설정은 이미 쓰고 있는 TOML 라이브러리를 읽기 전용으로 쓴다. 이 레포는 지금도 설정 파일을 프로그램이 쓰지 않고 읽기만 하는데, 그 관행을 그대로 이어 간다.

## 6. 화면과 로그

사용자에게 보이는 문구는 기존 `ua-refresh` 출력과 같이 영어로 쓰고, 달력에서 읽어 온 휴일 이름만 한국어 그대로 둔다.

```
$ gofer holiday sync
2021-01-01 ~ 2031-12-31 · 205 holidays stored
  ~/Library/Application Support/gofer/holiday/calendar.json

$ gofer holiday list 2026
2026-01-01  새해첫날
2026-02-16  설날 연휴
2026-03-02  쉬는 날 삼일절
…

$ gofer holiday check 2026-03-02
2026-03-02 (Mon)  holiday — 쉬는 날 삼일절

$ gofer ua-refresh run
2026-03-02 (Mon) is a day off (쉬는 날 삼일절) — skipping. Use --force to run anyway.

$ gofer ua-refresh status
launchd: installed · daily at 07:30 · workdays only · ~/Library/LaunchAgents/…
today:   2026-03-02 (Mon) · day off (쉬는 날 삼일절) · not running today
last run: 2026-02-27 07:30 → 07:41 · 3 updated · …
repos:
  …
```

쉬는 날에는 Slack으로 아무것도 보내지 않는다. 시작 알림도, 결과 요약도 보내지 않는다.

### 목록을 회복하지 못했을 때만 알림에 한 줄이 붙는다

경고를 표준 출력으로만 내보내면 `launchd.log` 파일에 쌓이고 아무도 열어 보지 않는다. 그래서 **자동 회복까지 실패한 경우에만** 일하는 날의 결과 요약 알림 맨 아래에 한 줄을 붙인다. 쉬는 날에는 알림 자체가 가지 않으므로, 이 줄은 일하는 날에만 보인다.

```
ua-refresh 2026-03-03 15:41 · 3 updated · 1 up to date · $2.10
✓ example-api  main     +13 commits   7m 12s  $1.40
…
로그: ~/Library/Logs/gofer/ua-refresh/2026-03-03.log
⚠️ holiday list only covers 2021-01-01~2031-12-31 — run `gofer holiday sync` (weekends still apply)
```

이 경고는 `last-run.json`에도 남으므로 `status`에서 다시 볼 수 있다.

## 7. 안전장치

| 상황 | 처리 |
|---|---|
| 목록을 한 번도 내려받지 않음 | 그 자리에서 한 번 받아 본다. 성공하면 그대로 진행, 실패하면 주말만 걸러 내고 실행하며 경고를 알림에 실어 보냄 |
| 목록이 깨졌거나 낡음 | 위와 같음. 원인을 경고에 덧붙임 |
| 자동 회복이 네트워크 문제로 실패 | 그날 실행을 막지 않는다. 다음 날 아침에 다시 시도한다 |
| 내려받기 실패 (`sync` 실행 중) | `sync`만 실패한다. 이미 저장된 목록은 그대로 두고 덮어쓰지 않음 |
| `--dry-run` | 자동 회복을 하지 않는다. 저장 파일을 바꾸지 않고 경고만 낸다 |
| 받은 내용에 공휴일이 하나도 없음 | 저장하지 않고 실패로 알림. 빈 목록으로 덮어써서 판정을 망가뜨리지 않기 위해서다 |
| 설정의 `extra`·`ignore` 날짜 형식 오류 | 설정을 읽는 시점에 전부 모아 보고. 기존 설정 검증 방식과 같다 |
| 쉬는 날 판정이 틀림 | 손해는 알림 두 건 또는 갱신 하루 지연. `extra`·`ignore`와 `--force`로 사람이 바로잡는다 |

## 8. 테스트와 검증

| 단계 | 방법 | 통과 기준 |
|---|---|---|
| 날짜 판정 | 고정한 날짜 여러 개를 `Calendar`에 넣어 본다 | 토·일, 공휴일, 대체공휴일, `extra`, `ignore`, 평일이 각각 맞게 나온다. `ignore`가 `extra`를 이긴다 |
| 목록 없음·낡음 | 저장 파일이 없는 경우, 깨진 경우, 범위 밖 날짜 | 주말만 판정되고 경고 문구가 나온다. 오류로 실패하지 않는다 |
| 달력 해석 | 실제 피드에서 잘라낸 고정 표본 | 공휴일 항목만 뽑고 기념일은 버린다. 캐리지 리턴과 접힌 줄을 바르게 처리한다 |
| 내려받기 | 표준 라이브러리의 시험용 서버로 가짜 응답 | 정상 응답, 오류 응답, 공휴일 0건 응답에서 각각 기대한 대로 동작한다. **네트워크에 나가지 않는다** |
| 게이트 | `CommandOptions.Now`를 금요일과 토요일로 고정해 `RunCommand` 실행 | 금요일은 평소대로 진행, 토요일은 Slack 전송·잠금·로그 파일·`last-run.json` 어느 것도 건드리지 않고 종료 코드 0 |
| 플래그 | 토요일 + `--force` | 평소대로 진행한다 |
| 전체 | `go test ./...`, `go vet ./...` | 통과 |
| 손으로 확인 | `holiday sync` → `holiday list 2026` → `holiday check` → `ua-refresh status` | 표시 내용이 위 6절과 같다 |

## 9. 결정 기록

| 결정 | 이유 |
|---|---|
| 공개 달력을 내려받아 파일로 굳힘 (매일 조회하지 않음) | 매일 아침 돌아가는 경로는 launchd 환경이라 이미 까다롭다. 여기에 외부 서버 접속을 더하면 서버가 느리거나 응답이 바뀌었을 때 그래프 갱신 전체가 영향을 받는다 |
| 정부 공식 조회 서비스 대신 공개 달력 | 공식 서비스는 인증키 발급 절차가 필요하다. 목적이 알림 소음 제거라서 판정이 하루 틀려도 손해가 작으므로, 절차 비용을 치를 만한 정확도 차이가 아니다 |
| 설정 파일과 저장 파일을 분리 | 한 파일이면 `sync`가 덮어쓸 때 사람이 적어 둔 임시공휴일과 주석이 날아간다. 기계가 쓰는 파일과 사람이 쓰는 파일을 섞지 않는다 |
| 판정할 수 없으면 실행하는 쪽으로 | 실행하지 않는 쪽으로 기울면 그래프가 조용히 늙는다. 반대는 최악이 알림 두 건이다 |
| 목록이 없어도 주말은 판정 | 주말 판정에는 파일이 필요 없다. 아무것도 못 하는 것보다 절반이라도 동작하는 편이 낫다 |
| 목록이 오늘을 못 덮을 때만 스스로 내려받음 | 사람이 `sync`를 잊으면 공휴일 판정이 조용히 멎는다. 확인한 달력이 2031년까지 담고 있어 이 경로는 5년 넘게 한 번도 실행되지 않으므로, "평소 경로에 네트워크를 두지 않는다"는 원칙과 부딪히지 않는다 |
| 갱신 전용 예약 작업을 만들지 않음 | 5년에 한 번 필요한 일에 launchd 작업과 설치·해제 명령을 새로 만드는 것은 과하다 |
| 회복 실패 경고를 Slack 알림에 실음 | 표준 출력으로만 내보내면 `launchd.log`에 쌓이고 아무도 열어 보지 않는다. 사람이 반드시 보는 통로는 알림뿐이다 |
| `--dry-run`은 자동 회복을 하지 않음 | 무엇을 할지 보여주기만 하는 명령이 저장 파일을 바꾸면 놀랍다 |
| plist는 그대로 두고 프로그램에서 판정 | launchd는 요일까지만 지정할 수 있고 공휴일은 불가능하다. 어차피 프로그램에서 판정해야 하므로 판정 지점을 한 곳에 모은다. 이미 설치를 마친 사용자가 다시 설치할 필요도 없다 |
| 사람이 직접 실행할 때도 건너뜀 | 부른 경로에 따라 다르게 행동하면 출력을 파이프로 넘기는 것만으로 동작이 바뀐다. 예외는 눈에 보이는 `--force`로만 만든다 |
| `workdays_only` 기본값 켜짐 | 쉬는 날 알림을 원하지 않는 것이 이 도구를 쓰는 이유다. 항목이 없는 기존 설정 파일도 켜진 것으로 본다 |
| 쉬는 날에 `last-run.json`을 건드리지 않음 | `status`의 "마지막 실행"이 건너뜀으로 덮이면 직전에 실제로 무엇이 갱신됐는지를 잃는다 |
| 다음 영업일 계산을 넣지 않음 | 지금 부르는 곳이 없다. 나중에 필요해지면 짧은 함수로 붙는다 |
| 달력 주소를 설정으로 뺌 | 코드는 한 줄도 늘지 않으면서 다른 나라 달력도 쓸 수 있다. 기본값은 한국이다 |
| 노동절·제헌절을 기본으로 쉬는 날 취급 | 목록이 주는 대로 따르고, 설정 주석으로 제외 방법을 안내한다. 쓰는 사람마다 답이 다른 항목을 코드가 정하지 않는다 |
| 조직 중립 | 예제·주석·문서에 특정 조직 정보를 넣지 않는다. 실제 값은 설정 파일에만 |
